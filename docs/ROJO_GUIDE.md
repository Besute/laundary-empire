============================================================
1. ТЕКУЩЕЕ СОСТОЯНИЕ
============================================================

Подтверждённая причина:
В начале default.project.json находились байты EF BB BF (UTF-8 BOM),
после которых шёл символ 7B ({). Rojo 7.7.1 не принял BOM при разборе
JSONC. Файл был пересохранен в UTF-8 без BOM.

Команда исправления:

$content = Get-Content .\default.project.json -Raw
[System.IO.File]::WriteAllText(
    (Resolve-Path .\default.project.json),
    $content,
    [System.Text.UTF8Encoding]::new($false)
)

Проверка:

Format-Hex .\default.project.json | Select-Object -First 2

Ожидаемое начало: 7B ... (не EF BB BF).

Сборка для проверки:

rojo build .\default.project.json --output .\build\LaundryEmpire-test.rbxl

Важно: исправление кодировки ещё не означает, что build, live sync и целостность
Place1 уже проверены. Отмечать PASS только после фактического выполнения теста.

Ранее подготовлены TODO.md, DECISIONS.md, CHANGELOG.md, CHECKPOINT.md,
GameConfig.lua и EconomyConfig.lua. Конфиги добавлялись в
ReplicatedStorage.Shared.Config открытого Place1. Проверки JSON/маппинга
и загрузки модулей через require ранее проходили. Игровые механики пока
не реализованы. Экономические значения — предварительные гипотезы для
плейтеста, не финальный баланс. Place1 не публиковать и не перезаписывать
без резервной копии и отдельной проверки.

3. КАК НЕ СЛОМАТЬ ROJO ПОВТОРНО
============================================================

ГЛАВНОЕ ПРАВИЛО: default.project.json и другие JSON/JSONC-файлы,
которые читает Rojo, сохранять в UTF-8 БЕЗ BOM.

VS CODE:
1. Нажать на индикатор кодировки в нижней панели.
2. Выбрать Save with Encoding.
3. Выбрать UTF-8.
4. Не выбирать UTF-8 with BOM.
5. После правок project-файла проверить первые байты через Format-Hex.

POWERSHELL — пересохранение одного файла без BOM:

$path = (Resolve-Path .\default.project.json).Path
$content = Get-Content .\default.project.json -Raw
[System.IO.File]::WriteAllText(
    $path,
    $content,
    [System.Text.UTF8Encoding]::new($false)
)

Перед преобразованием других файлов сделать копию. Не запускать массовое
перекодирование папок без необходимости.

ПЕРЕД КАЖДЫМ BUILD/SYNC:
[] Перейти в корень проекта.
[ ] Проверить, что используется нужный default.project.json.
[ ] Убедиться, что первые байты файла — не EF BB BF.
[ ] Проверить JSON/JSONC и пути маппинга.
[ ] Убедиться, что Aftman/Rojo запускаются ожидаемыми версиями.
[ ] Выполнить build в отдельный тестовый файл.
[ ] Перед live sync убедиться, что резервная копия Place1 существует.

НЕ ДЕЛАТЬ:
- Не сохранять project-файлы как UTF-8 with BOM.
- Не полагаться на то, что PowerShell читает файл: это не гарантирует,
  что JSONC-парсер Rojo его примет.
- Не запускать Rojo из случайной папки.
- Не синхронизировать основной Place1 до проверки резервной копии и маппинга.
- Не направлять build в файл основного рабочего place.
- Не менять одновременно кодировку, маппинг и версии инструментов:
  так труднее локализовать новую ошибку.

ЕСЛИ ОШИБКА ПОВТОРИЛАСЬ:
1. Остановить rojo serve сочетанием Ctrl+C.
2. Не публиковать и не сохранять сомнительную сборку поверх Place1.
3. Выполнить Format-Hex для default.project.json.
4. Если начало EF BB BF — пересохранить UTF-8 без BOM.
5. Повторить build в отдельный файл.
6. Если BOM отсутствует — проверить JSON/JSONC-синтаксис, пути маппинга,
   версии инструментов и полный текст ошибки.
7. Не удалять и не пересоздавать объекты Studio наугад.

5. ОБНОВЛЁННЫЙ ПЛАН MVP LAUNDRY EMPIRE
============================================================

ЗАФИКСИРОВАННЫЕ РЕШЕНИЯ:
- Загрузка вещей: MENU — выбор типа/количества вещей, анимация загрузки,
  визуальное перемещение одежды в барабан.
- Камера: HYBRID — обычная Roblox-камера от третьего лица и отдельный
  вид сверху/под углом в строительном режиме.
- Найм: GRADUAL — сначала игрок выполняет работу сам, затем нанимает
  сотрудников по ролям.

[ ] Этап 1. Каркас проекта и стартовый мир
    Структура модулей, стартовая заброшенная прачечная у торгового центра,
    участки владения, точка появления, конфиги, запуск сервера и клиента.

[ ] Этап 2. Основной игровой цикл
    NPC-клиенты, путь к стойке, заказ, очередь, терпение, выдача заказа,
    завершение и базовая награда.

[ ] Этап 3. Стирка и сушка
    Стиральные машины и сушилки, меню загрузки, анимация барабана,
    циклы стирки/сушки, состояния оборудования и обработка ошибок.

[ ] Этап 4. Экономика и прогресс
    Деньги, расходы, XP, уровни, разблокировки, сохранение прогресса,
    серверная проверка денежных операций.

[ ] Этап 5. Чистота, качество и рейтинг
    Грязь помещения, качество обслуживания, рейтинг и влияние на поток
    клиентов и доход.

[ ] Этап 6. Магазин и улучшения
    Покупка оборудования, инвентарь, размещение, улучшения машин,
    цены и требования разблокировки.

[ ] Этап 7. Сотрудники
    Найм по ролям, зарплаты, назначение задач и постепенная автоматизация.

[ ] Этап 8. Расширение и строительство
    Расширение помещения, строительная камера, новые зоны/этажи,
    парковка и дополнительные объекты.

[ ] Этап 9. Поздние системы после стабильного MVP
    Реклама, износ и поломки, день/ночь, воры и полиция, транспорт,
    недвижимость, аукционы, корпоративные заказы, несколько районов,
    Rebirth и поздняя мета-прогрессия.

Не начинать поздние системы, пока цикл
«клиент → заказ → стирка → сушка → выдача → награда»
не работает стабильно и не сохраняет данные.

6. ТЕХНИЧЕСКИЕ ПРАВИЛА РЕАЛИЗАЦИИ
============================================================

- Сервер — источник истины для денег, заказов, наград, инвентаря и прогресса.
- Клиент отвечает за UI, ввод, камеру и визуальные эффекты.
- Проверять все RemoteEvent/RemoteFunction на сервере.
- Не доверять клиенту цены, суммы наград, владение предметами
  и подтверждение завершения игровых операций.
- DataStore реализовывать с обработкой ошибок и защитой от потери данных.
- Оффлайн-доход не входит в MVP.
- Rebirth, сложная полиция, аукционы и несколько районов — не первый релиз.
- Значения EconomyConfig.lua пока являются гипотезами для плейтеста.
- Проверять производительность NPC, машин и UI при нескольких игроках.
